# ADR 0010 — IPC: one event channel, signals at the kernel's edge, descriptors as vnodes

**Status:** accepted · 2026-10-10 · **milestone:** M6

## Context
M6 is what Wayland needs of a kernel (ADR 0004): unix sockets that pass file
descriptors, shared memory, `poll`/`epoll`, signals, pipes. The exit test is
libwayland's own test suite, and two processes exchanging a shared-memory
buffer by descriptor over a socket and mapping it coherently.

## Decisions

### Everything that blocks sleeps on one event channel
`sched/events` is a generation counter and one wait queue. Whatever changes
state that somebody might be waiting for -- bytes in a pipe, a connection, a
child's exit, a signal, a lock released -- calls `notify()`. A waiter takes a
snapshot before it looks, and `wait(snapshot)` returns at once if anything was
notified since. Everyone is woken by everything and looks again.

This is what makes `poll` and `epoll` trivial -- they wait for several
unrelated things with no registration on any of them -- and it means no
subsystem shares a lock with another to avoid lost wakeups. Deadlines ride on
the same wait: the timer tick notifies when the earliest one passes.

*Rejected:* a wait queue per object. It is the scalable design and the wrong
one for now: `poll` over N objects needs N queue entries and a way to back out
of them, for a system with a dozen processes.

### Every descriptor is still a vnode
Pipes, sockets, shared memory objects, epoll sets, timerfds, signalfds and
eventfds are `Vnode`s on an anonymous filesystem, behind the same `File` as a
file on disk. `read`, `write`, `close`, `fstat`, `dup` and descriptor passing
need no special cases; a vnode gained `poll()` and `shared_page()`.

One spinlock guards the state of all the IPC objects. User memory is never
touched with it held: data crosses through a kernel buffer, since touching
user memory can fault.

### Signals are acted on only at the return to user mode
Posting a signal sets a bit and notifies. The target acts on it itself, when
it is about to return to ring 3 from a system call or an interrupt -- the one
place its whole user state is at hand. A handler's frame goes on the user
stack with every register and the FPU image; `sigreturn` restores them through
`iretq`, because `SYSRET` cannot restore `rcx` and `r11`.

A blocking call interrupted by a signal returns an internal "restart" code,
resolved at delivery: re-executed for `SA_RESTART` handlers and for signals
that turn out to need no handler, `EINTR` otherwise. Faults in user mode
(`#PF`, `#GP`, ...) go through the same machinery, so a program can handle its
own `SIGSEGV`; unhandled, they kill it as before.

Stopping and continuing (`SIGSTOP`, `SIGTSTP`, `SIGCONT`) are not implemented:
those signals are ignored by default. There are no process groups.

### Descriptors in flight are references held by the message
`sendmsg` with `SCM_RIGHTS` takes a reference to each open file and attaches
them to the first segment of the message on the peer's queue. `recvmsg`
installs them as new descriptors in whichever process reads that segment's
first byte, and never merges two messages that both carry files into one
receive. A socket closed with files still queued closes them.

Sockets are `AF_UNIX`, `SOCK_STREAM` only. A bound socket's name is a node in
the filesystem (tmpfs: FAT has nowhere to put one); `connect` completes
without waiting for `accept`, as on Linux.

### Shared memory is eager, and shared across fork by a page-table bit
A `memfd` allocates all its pages when it is sized. `mmap(MAP_SHARED)` maps
those same frames with one more reference each and a software bit in the
entry; `fork` copies such an entry as it is instead of making it
copy-on-write. `MAP_SHARED | MAP_ANONYMOUS` is the same object without a
descriptor. Files on disk still cannot be mapped shared: there is no page
cache.

### Small things programs assume
`O_CLOEXEC` and `FD_CLOEXEC`, honoured by `execve`; `fcntl`; `flock` with real
semantics (libwayland's socket lock files depend on them); `pread`/`pwrite`;
`/dev/fd`; unlinking an open file on tmpfs; `x86_64-sirius-gcc -pthread`
(accepted, links nothing); `sleep` interruptible by signals.

## Consequences
- **No threads** -- at the time. `pthread_create` failed, and four of
  libwayland's 141 tests with it. Threads came later (ADR 0012), and the
  whole suite passes.
- Every waiter wakes on every event. Fine now; the first thing to change if a
  hundred processes ever sleep at once.
- A handler's third argument points at the kernel's own saved-context
  layout, not a POSIX `ucontext_t`.
- Signals posted to a process running in user mode on another CPU are noticed
  at its next timer tick: up to 10 ms.
- `siriusd` could now sleep in `poll` instead of redrawing continuously; it
  does not yet.
- mlibc gained a third patch (`memfd_create` without the Linux option) and
  the GCC patch one line (`-pthread`).
